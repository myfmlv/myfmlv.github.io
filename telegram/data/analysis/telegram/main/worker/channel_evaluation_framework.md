# Telegram Channel Evaluation Framework

## Core principle
- No channel is disposable.
- Every channel is a sensor with a different role.
- Do not rank channels by polish, length, or formal tone alone.
- Evaluate each channel by factual reliability, inference quality, domain strength, timing value, and recurring failure modes.

## Evaluation dimensions

### 1. Factual reliability
- Are the underlying facts, numbers, and event descriptions usually correct?
- Does the channel misstate headlines, dates, entities, or market moves?
- Does the channel correct itself when facts change?

### 2. Inference quality
- Does the channel merely relay, or does it infer well?
- Are conclusions logically connected to evidence?
- Does it overreach, moralize, or jump too fast from structure to trade?

### 3. Timing value
- Is the channel early, on time, or late?
- Does it catch emerging shifts before more polished channels summarize them?
- Does it detect changes in conviction or regime earlier than others?

### 4. Domain strength
- In which topics is the channel especially useful?
- Examples: oil, Iran war, shipping, semis, Korea strategy, defense, FX, rates.

### 5. Failure modes
- Typical mistakes or biases.
- Examples: overconfidence, political over-interpretation, premature certainty, low signal-to-noise, poor sourcing.

## Operating rule for briefing
- Do not discard short, rough, or chatty-looking messages by default.
- Preserve channel-specific interpretive value even when wording looks informal.
- Briefings should synthesize cross-channel changes, not reward only polished prose.
- Repeated high-value intuitions from a channel should raise that channel's weight in the relevant domain.

## Escalation rule
- If a channel repeatedly fails on both facts and inference, surface the channel name to the user for final judgment.
- Final keep/drop decision belongs to the user.
